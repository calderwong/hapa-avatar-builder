## Recovery, limits and learning

Owner backups precede changes. Do not restore whole stores over later work:
select an older cut/revision through its owner or use the shared manager's
normal reversible operations. The immutable package candidate and original
dependency hashes remain in private evidence. No API or shared host restart
was needed. No source audio/video bytes were changed.

Two staging mistakes are preserved: the system Python lacks the newer
tarfile extraction filter parameter, and packing continued after that staging
failure. The corrected pass validates every archived member/path before
extraction and inspects staging success before packing. The failed pack
exited cleanly without an artifact. This was a harness error, not an app defect.

Reusable lesson candidate: keep operator identity, active collection eligibility
and visible fallback separate. Repair bootstrap in the shared owner rather
than merging identities or expanding an existing Hand's surface list.
Native source identity and retained old cue revisions provide the modular proof;
a matching label alone does not. Existing full-app/Tarot/nonzero bookmark,
remaining navigation criteria, permanent package delivery and prepared-audio
integration still require their own evidence. LL-917 is not closed here.
