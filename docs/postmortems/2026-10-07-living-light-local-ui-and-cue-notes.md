## Implemented behavior

Static Builder launches that retain a LAN HTTP listener now add one literal `127.0.0.1` UI listener inside the same API process. The default is the primary port plus ten, skipping reserved/Phone ports; canonical `8797` uses `8807`. Loopback root requests redirect once, retaining query parameters. Phone Card, API, asset and LAN requests retain their original listeners. API-only or already-loopback launches add no companion. `--local-ui-port` / `HAPA_AVATAR_LOCAL_UI_PORT` can override or explicitly disable it with zero; invalid/reserved/colliding ports refuse without taking another owner's socket.

Living Light checks the actual server listener's private metadata; headers cannot claim a loopback bind. Browser bootstrap requires an empty body, exact Host/Origin, same-origin browser provenance and explicit first-party intent. Cookies remain HttpOnly, Strict and process-scoped. API clients remain agents. Only a typed pre-dispatch 401 can trigger the single coalesced browser retry; ambiguous failures are retained for explicit recovery.

The existing Electron launcher now qualifies the companion's local address, same API boot metadata and actual Builder HTML before assigning its trusted renderer origin. Foreign/reserved origins and mismatched processes fail closed. This is local configuration validation, not cryptographic OS attestation. The dedicated shell's HTML probe follows at most one redirect; existing single-instance/focus and credential-sender guards stay in place. Local probes have an absolute 1.5-second deadline and a 16 KiB response ceiling. No extra app, process, playback owner or authoring database is introduced by the socket extension.

One shared note component serves Things, saved Journeys and saved instances. Optional cue ranges must fall inside the observed saved interval; changed unsaved schedules cannot replace the note's observation. Notes, retractions and immutable histories page through the same native owner. Draft recovery preserves edit identity, original comparison text, expected revision and pending idempotency key. Changing text invalidates that pending operation. Incoming edits and new recipes require comparison before replacing a dirty local draft. Saved Journey card note counts refresh after note changes. Technical identities are available in optional details, and the text field spans the inspector width.
