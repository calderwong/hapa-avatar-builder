## Implemented path

The same Builder-owned native authoring service now saves and lists Journey drafts, reads exact pinned revisions and immutable history, protects edits with expected-head comparisons, and resolves idempotent retries. The canonical Song owner must confirm the exact Song ID before saving; a Journey cannot change songs through an ordinary edit. Source and renderer readiness remain separate: saving accepts unresolved drafts and does not promote fake source bindings to ready.

Journey birth atomically materializes only referenced Things and records the Journey plus recoverable custody/delivery intents. Actual Card custody uses the existing owner and preserves one root receipt per Card through later edits. This is local custody, not minting or acknowledged publication. Metadata browsing creates no authoring DB or Card cores. Current-head “used in” references are derived from saved Journey revisions.

The Echo editor creates Continuous Tunnel or Location tour drafts, adds Things from the library, replaces modules by capability, edits interval durations and supported numeric instance overrides, resets/duplicates/removes uses, reorders Locations with explicit passage reconnection, and provides undo/redo. Timing edits preserve total planned source time; no measured events are stretched. Draft text and pending idempotency metadata can recover locally across reload; saved truth stays with Builder. Loading a saved revision while a draft is dirty offers comparison and explicit replacement rather than silently dropping the draft.

Saved Journey and instance note targets now resolve actual native revisions. A cue range must fall within the observed instance interval; an arbitrary valid range elsewhere in the song is rejected. Every non-Thing note requires an observed revision. Frontend Journey/cue note editing, forks with explicit conversion preview, presets, import/export and CLI/Hand parity remain unfinished.

## Reuse and lesson

Reused the existing Echo workbench and new single native authoring spine; no additional app, playback owner, notes database or per-tile renderer was created. Saved recipes reference original module identities instead of copying shaders or mutating reusable definitions. The strongest useful checks were independent-client conflicts, transaction rollback and route reconnection with unchanged total time. A mouse action returning successfully did not prove navigation; observing the selected mode and post-navigation DOM prevented a false lifecycle pass. Keep authoring, renderer readiness and native visual acceptance distinct. This is a Decision/Lesson Card candidate derived from the attributed chat, not canon or a generalized protocol result.
